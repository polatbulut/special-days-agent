5 · End-to-end flow

Sources and the airport list in, two Parquet objects out. Collection and scoring are this repo; the Spark enrichment that builds the lakehouse tables runs on THY on-prem from a separate repo and is still in progress. Downstream forecasting reads the result by path.

  • Two repos, one pipeline. Collection, the canonical record and scoring live in special-days-agent. The Spark enrichment that builds and writes the lakehouse tables is a separate repo on THY on-prem and is still in progress — the dashed border marks it. Consumers read the output by path, so the downstream contract does not depend on which side produced it.
  • This repo can also write the objects directly. The bundled --obs sink performs the same enrichment in-process and encodes Parquet with pyarrow, no cluster involved — that is the standalone CLI / CronJob path, and it is what the code in this repo does today. Treat it as the local and dev route; the Spark job is the on-prem production route.
  • Where the airport list actually enters. In code, nearest-airport mapping is the first sub-stage of enrich() and runs before scoring, because both scorers read the airport off the record — the heuristic adds a proximity term and the LLM prompt embeds the mapped IATA code. The diagram draws it feeding the scorer for that reason.
  • The scorer is one swappable interface. Default is an offline heuristic needing no key and no network. Azure / OpenAI / vLLM are opt-in and share one gateway. A failed or unparseable model reply degrades that single record to the heuristic and logs it — it never aborts the run.
  • Idempotent by construction. Each dataset is a single object at a fixed key, overwritten every run, with a deterministic record_key hashed from the business key. Re-running is safe: no partitions to reconcile, no append-duplicates, no compaction.
  • Nationwide holidays survive the explode. They have no single airport, so feature rows keep airport = NULL with country populated rather than being dropped — they are the largest signal in the feed.
